SLGPlus manipule des données d'élèves et des accès à des services tiers. Cette page expose les mécanismes déjà en place, les risques connus et les bonnes pratiques que vous devez appliquer pour maintenir la sécurité du système.

## Authentification sans compte nominatif

Au lieu d'un système de nom d'utilisateur et mot de passe personnels, SLGPlus repose sur des rôles partagés (élèves, bvs, admin, profs). Chaque rôle est protégé par un PIN stocké sous forme de hash dans `users_accounts.pin_hash`. Lors de la connexion, la méthode `check_password_hash` de Werkzeug compare le PIN saisi avec le hash.

```python
check_password_hash(account["pin_hash"], pin)
```

Aucun mot de passe ou PIN n'est jamais stocké en clair. Seul le hash est conservé. L'administrateur peut changer un PIN via `/admin/setpin` sans connaître l'ancien.

## CORS et contrôle des origines

L'API Python active CORS de manière permissive dans `app.py` :

```python
CORS(app, resources={r"/*": {"origins": "*"}}, supports_credentials=True)
```

<Info>
  Cette configuration est pratique lors du développement car elle autorise n'importe quel site à appeler l'API. En production, il est recommandé de restreindre les origines autorisées à vos domaines connus.
</Info>

Le middleware PHP du forum, lui, est plus restrictif. Le fichier `extend/CorsMiddleware.php` autorise explicitement trois origines :

```php
protected array $allowedOrigins = [
    'https://forum-slgplus.great-site.net',
    'https://slgplus.shares.zrok.io',
    'https://api-slgplus.shares.zrok.io',
];
```

Les en-têtes autorisés incluent le `skip_zrok_interstitial` nécessaire pour contourner la page de confirmation zrok.

## Les règles de base à appliquer

- **Rotation des clés API** : changez vos clés Gemini et Flarum au moins une fois par trimestre, ou immédiatement si vous suspectez une fuite.
- **Filtrage des origines CORS** : en production, remplacez `origins: "*"` par une liste explicite dans `app.py`.
- **Accès au dashboard** : le dashboard écoute sur `0.0.0.0:9000` mais ne doit être accessible que depuis le réseau local du serveur. Ne l'ouvrez pas sur Internet sans reverse proxy et authentification renforcée.
- **Mises à jour des dépendances** : Flarum, Flask et les extensions PHP reçoivent régulièrement des correctifs de sécurité. Planifiez une revue mensuelle via `composer update` et `pip list --outdated`.
